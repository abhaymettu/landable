## How each tool scores

**Kodus.** Each criterion is pass or fail. A maturity level is reached when at least 80% of its non-skipped criteria pass and every lower level is reached too (`src/engine/scorer.ts:L33-121`, `LEVEL_THRESHOLD = 0.8` at `src/types/index.ts:L11`). The 4 `requiresLLM` criteria are skipped and excluded without `--ai` (`src/engine/analyzer.ts:L68-75`), so Level 5 then rests on `bundle-analysis` alone. A `thresholds` block in the config template (`src/engine/config.ts:L122-127`) is never read. The LLM client posts to an OpenAI-compatible endpoint, default `https://api.openai.com/v1`, default model `gpt-5.6-terra` (`src/engine/llm-client.ts:L3-4, L47`). Level counts: L1 4, L2 10, L3 12, L4 8, L5 5.

**Kodus path semantics** (`src/pillars/utils.ts:L6-23`). A pattern without `*` is `existsSync(join(repo, p))`: file or directory, and case-sensitivity follows the host filesystem (case-insensitive on default macOS APFS, sensitive on Linux), so results can differ by OS. A pattern with `*` goes to fast-glob with `dot: true`, files only, no ignore list, first match wins. A port should pick case-sensitive matching to mirror Linux CI.

**AFC.** Each signal returns a graded pass in [0, 1]. Agent score = 100 * sum(pass * weight) / sum(weights), rounded to 0.1 (`lib/scoring/scorer.ts:L25-50`). Overall = mean of the 9 agent scores (`scorer.ts:L72-75`). Weight sums per agent: claude-code 7.6, cursor 8.7, devin 8.4, gpt-5-codex 7.9, kimi-cli 7.5, gemini-cli 9.2, aider 7.1, openhands 10, pi 7.5 (`lib/scoring/weights.ts:L20-273`).

**AFC path semantics** (`lib/scoring/signals/helpers.ts`). Every lookup is case-insensitive per path segment, exact spelling preferred (L59-128). `firstExisting` accepts files or directories (L155-168); `firstFile` accepts files only (L177-189). Reads are capped at 1 MiB (L22, L193-218). Symlinks that leave the repo count as empty placeholder files (L27-57). `walkFind` skips node_modules, .git, vendor, target (L220-263). Signal groups come from the site copy: `lib/check-content/agent-files.ts` (6) and `lib/check-content/repo-basics.ts` (11).

**AFC already uses agentready's input contract.** Its live scorer rebuilds a repo at a ref from the host tree API (`GET /repos/{o}/{r}/git/trees/{ref}?recursive=1`, with per-subtree refetch on truncation, `lib/live-score/hosts.ts:L115-153`), writes empty placeholders for every path, and fetches real bytes only for 15 files: README.md, README.rst, README.txt, README, AGENTS.md, CLAUDE.md, AGENT.md, .claude/CLAUDE.md, .claude/AGENTS.md, GEMINI.md, .openhands/setup.sh, .aider.conf.yml, package.json, pyproject.toml, .gitignore (`lib/live-score/content-files.ts:L8-24`, `materialize.ts:L133-170`). `scripts/parity-check.ts` asserts identical scores against a clone (README.md L48). Its committed `data/rank.db` holds 401 repos x 17 signals (6817 `signal_result` rows, counted with sqlite3 in immutable read-only mode) but stores no commit sha, so it can serve as a port parity fixture only at HEAD as of `last_scored_at`.

## Notes for the port

- No item in either tool calls the GitHub API. Kodus `branch-protection` is a regex over `.github/settings.yml` and CONTRIBUTING.md, so it is DET-TREE. The only DET-API item is Kodus `no-outdated-deps`, which as written compares a file's mtime to the wall clock; on a fresh clone it always passes when a lockfile exists. The port needs the last commit date of that path.
- Kodus `type-checker` has a measurement bug: its comment stripper (`src/pillars/style-linting.ts:L365-368`) also deletes `//` inside strings and `/* ... */` spans across globs. A replica of that regex, run in node on three sample tsconfigs, returned true for a bare `{"compilerOptions":{"strict":true}}` and PARSE_ERROR for one with a `$schema` URL and for one with `paths` `@/*` plus `include` `src/**/*.ts`. Strict TypeScript repos with either pattern fail the check.
- Lenient passes to keep in mind when reading correlations. Kodus: `linter` passes on any Cargo.toml, `formatter` on any go.mod, Cargo.toml or C# project, `type-checker` on any statically typed language, `test-framework` on any Cargo.toml or Package.swift, `test-script` on npm's default failing test script and on any Gradle, Maven, Cargo, .NET, Rakefile or Swift build file, `version-pinned` on any go.mod or gradle.properties, `deploy-pipeline` on the bare word release or publish anywhere in CI YAML. AFC: `linter` passes on a bare setup.cfg, `type_config` on any tsconfig.json without strict mode, `tests` on an empty tests/ directory, `size` scores tiny repos below mid-size ones.
- Kodus content reads go beyond the brief's small-file set: build.gradle(.kts), pom.xml, Gemfile, composer.json, Cargo.toml, Makefile, setup.cfg, every *.csproj (recursive), jest/vitest configs, phpunit.xml, detekt and eslint configs, .pre-commit-config.yaml, .github/settings.yml, CONTRIBUTING.md, and every CI file. All are small text files at fixed paths, so the tree-plus-contents contract still holds; the fetch list grows to about 40 paths plus all workflow YAML and *.csproj files.
- AFC's own README.md L53 says its weights come from each agent's documentation, not from measured agent success, with a benchmark harness planned for 1.0. The validation study is the measurement it lacks.
